# Puesta en marcha en el NAS (192.168.2.181)

El servicio Reflex corre **en el propio NAS**. Código en `E:\Sistemas_Dev\`
(share `Sistemas_Dev$`, unidad `X:`). RRHH abre `http://192.168.2.181:3000`
(o el lanzador `INSEVIG_Demo.exe` desde `Apps_Empresa$\Lanzadores\`).

> Versión mínima "que funcione ya": app en `:3000` como servicio Windows.
> HTTPS + dominio bonito con Caddy es endurecimiento posterior (ver `README.md`).

## 1. Verificar qué falta

En el NAS, como Administrador, dentro del proyecto:

```powershell
cd E:\Sistemas_Dev\NOMINA_ROLES_SISTEMA_INSEVIG
.\deploy\windows\verificar-requisitos.ps1
```

## 2. Instalar lo que marque FALTA

| Requisito | Cómo | Nota |
|---|---|---|
| **Python 3.12+ x64** | `winget install -e --id Python.Python.3.12` | per-machine, "Add to PATH" |
| **Node.js LTS** | `winget install -e --id OpenJS.NodeJS.LTS` | Reflex baja Bun solo; Node ayuda |
| **ODBC Driver 17 for SQL Server** | descargar `msodbcsql17` de Microsoft | **NO** el 18 (fuerza cifrado) |
| **PostgreSQL 16** | `winget install -e --id PostgreSQL.PostgreSQL.16` | crear BD `insevig_app` + usuario |
| **NSSM** | de nssm.cc → `C:\insevig\tools\nssm.exe` | registra el servicio Windows |
| Carpetas | `mkdir C:\insevig\logs C:\insevig\tools C:\insevig\var\storage` | logs y storage del servicio |

Crear la BD de la app (en `psql`):

```sql
CREATE DATABASE insevig_app;
CREATE USER insevig_app WITH PASSWORD 'una_clave_fuerte';
GRANT ALL PRIVILEGES ON DATABASE insevig_app TO insevig_app;
```

Logins de SQL Server con permiso mínimo (no usar `sa` — ver `README.md` §3).

## 3. Configurar `.env`

```powershell
copy deploy\.env.prod.example .env
notepad .env
```

Completar: `SQLSERVER_PWD_RO/RW`, `SUPABASE_URL/KEY`, `APP_DB_URL` (la BD de arriba),
`SECRET_KEY` (aleatorio largo), `STORAGE_DIR=C:\insevig\var\storage`. Email/IA
pueden quedar en `console` / `none` para arrancar.

## 4. Desplegar

```powershell
.\deploy\windows\deploy-nas.ps1
```

Hace venv + `pip install`, healthcheck, `alembic upgrade`, crea el admin,
abre el firewall TCP 3000, registra el servicio `insevig-web` (auto-arranque,
reinicio si falla) y lo levanta. Al terminar: `http://192.168.2.181:3000`
(login `admin` / `admin` → cambiar clave).

## 4b. Migrar el histórico de préstamos (una vez)

El historial viejo de préstamos vive en un SQLite (`Saldo_prestamos_driver.db`,
antes en el recurso SMB). Cargarlo una vez en Postgres:

```powershell
.\.venv\Scripts\python -m core.migrations_legacy.sqlite_to_appdb "<ruta>\Saldo_prestamos_driver.db"
```

Es idempotente (correrlo de nuevo no duplica). Sin esto, `/prestamos/historial`
solo muestra lo que hay en SQL Server (RPINGDES + RPHISTOR).

## 5. Actualizar después

```powershell
cd E:\Sistemas_Dev\NOMINA_ROLES_SISTEMA_INSEVIG
.\deploy\windows\deploy-nas.ps1 -SoloActualizar
```

`git pull` + deps + `alembic` + reinicio del servicio. Los usuarios recargan (F5).

## 6. Acceso desde fuera de la oficina (HTTPS público)

Montado en este NAS con **DuckDNS + Caddy**:

- Dominio: `insevig-rrhh.duckdns.org` (mantener la IP pública actualizada en
  duckdns.org — cliente/tarea programada en el propio NAS).
- Router: reenviar **80 y 443** → `192.168.2.181`.
- **Caddy** como servicio `insevig-caddy` (NSSM), `Caddyfile` en
  `C:\insevig\caddy\` (ver `deploy/Caddyfile`): termina HTTPS (cert Let's
  Encrypt automático) y hace `reverse_proxy 127.0.0.1:3000`. No hay split a
  `:8000` porque la app corre en `--single-port`.
- IIS (W3SVC) debe estar **detenido/deshabilitado**: su sitio por defecto
  ocupa el 80 y bloquea a Caddy.
- `:3000` queda solo en localhost; hacia Internet solo sale Caddy (443).

Acceso interno sigue igual: `http://192.168.2.181:3000`.

> Sistema con datos de sueldos + credenciales ya filtradas una vez en git:
> antes de exponerlo, **rotar** la key de Supabase y el login `sa`, y valorar
> un candado previo (Cloudflare Access / VPN) en vez de solo el login de la app.
